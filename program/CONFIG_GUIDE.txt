Этот документ подробно описывает файл config.ini: все секции, все параметры,
допустимые значения и примеры. Если вы просто хотите «чтобы работало» —
достаточно README.txt. Если хотите тонко настроить — читайте дальше.


--------------------------------------------------------------------------------
  1. ОБЩИЕ ПРАВИЛА
--------------------------------------------------------------------------------

1. Файл config.ini лежит рядом с программой (SnapshotVault.exe или
   snapshotvault-cli). При первом запуске создаётся автоматически.

2. Формат — стандартный INI (как в Windows). Секции в квадратных скобках
   [ИмяСекции], параметры в виде ключ = значение.

3. Комментарии начинаются с точки с запятой (;) или решётки (#).
   Всё, что после них до конца строки — игнорируется.
   Пример:
       backup_base = ~/SnapshotVault   ; куда сохранять бэкапы

4. Регистр в именах секций и ключей ВАЖЕН.
   [General] и [general] — разные секции. Пишите точно как в примерах.

5. Многострочные значения (несколько путей, несколько исключений) пишутся
   с отступом (4 пробела или таб) в начале каждой строки. Пример:
       paths =
           C:/Users/user/Documents
           D:/Backup
   Без отступа configparser решит, что это новый ключ, и выдаст ошибку.

6. Пути можно писать с ~ (домашняя папка). На Windows ~/Documents
   превратится в C:\Users\ВашеИмя\Documents. На Linux — в /home/имя/Documents.

7. Прямые слэши (/) и обратные (\) в путях работают одинаково.
   C:/Users/user/Documents и C:\Users\user\Documents — одно и то же.

8. Программа читает config.ini ТОЛЬКО при запуске (или при нажатии
   «🔄 Перезагрузить» в GUI). Если вы отредактировали файл в Блокноте —
   нажмите «Перезагрузить» или перезапустите программу.


--------------------------------------------------------------------------------
  2. СЕКЦИЯ [General] — ГЛОБАЛЬНЫЕ НАСТРОЙКИ
--------------------------------------------------------------------------------

Эти настройки применяются ко всем профилям, если в профиле не указано иное.

--- backup_base ---
  Куда сохранять снимки. Для каждого профиля создаётся подпапка с его именем.
  Тип: путь (строка).
  По умолчанию: ~/SnapshotVault
  Примеры:
      backup_base = ~/SnapshotVault
      backup_base = D:/Backups/SnapshotVault
      backup_base = /mnt/data/snapshots

--- logging_enabled ---
  Вести ли лог-файлы (backup.log в папке каждого профиля).
  Тип: true / false
  По умолчанию: true
  Пример:
      logging_enabled = true

--- log_level ---
  Уровень логирования: DEBUG, INFO, WARNING, ERROR.
  Тип: строка.
  По умолчанию: INFO
  Пример:
      log_level = INFO

--- debug ---
  Подробный отладочный вывод (в лог и в консоль). Включайте только
  для диагностики проблем.
  Тип: true / false
  По умолчанию: false
  Пример:
      debug = false

--- hash_enabled ---
  Считать ли SHA-256 для каждого файла при создании снимка. Включено —
  надёжнее (можно проверить целостность), но медленнее на больших файлах.
  Тип: true / false
  По умолчанию: true
  Пример:
      hash_enabled = true

--- external_enabled ---
  Глобально разрешить синхронизацию на флешки / внешние ЖД с меткой
  SV_BACKUP_ALLOW.txt.
  Тип: true / false
  По умолчанию: true
  Пример:
      external_enabled = true

--- external_rotation_n ---
  Сколько последних снимков хранить на носителе. 0 — не удалять никогда.
  Тип: целое число >= 0.
  По умолчанию: 5
  Пример:
      external_rotation_n = 5

--- external_search_all ---
  Искать метку на ВСЕХ томах (true) или только на съёмных носителях (false).
  true — работает и для внешних ЖД, и для сетевых шар с меткой.
  false — только флешки (DRIVE_REMOVABLE на Windows).
  Тип: true / false
  По умолчанию: true
  Пример:
      external_search_all = true


--------------------------------------------------------------------------------
  3. СЕКЦИЯ [Exclude] — ГЛОБАЛЬНЫЕ ИСКЛЮЧЕНИЯ
--------------------------------------------------------------------------------

Здесь перечисляются маски файлов и папок, которые НЕ нужно бэкапить.
Эти исключения применяются ко всем профилям (дополняют встроенные).

--- patterns ---
  Список масок. По одной на строку, с отступом 4 пробела.
  Тип: многострочный список.
  Пример:
      [Exclude]
      patterns =
          *.tmp
          ~$*
          .git
          .git/*
          node_modules
          node_modules/*
          __pycache__
          *.log
          *.bak

  Правила масок:
  - Маска без / (например, *.tmp) — совпадает по имени файла/папки.
  - Маска с / (например, .git/*) — совпадает по относительному пути.
  - Папка исключается целиком, если её имя совпало с маской.

  Встроенные исключения (их не нужно дублировать):
      *.tmp, ~$*, .git, .git/*, node_modules, node_modules/*,
      __pycache__, __pycache__/*, *.swp, *.swo, .DS_Store,
      Thumbs.db, desktop.ini


--------------------------------------------------------------------------------
  4. СЕКЦИЯ [Profile:ИМЯ] — НАСТРОЙКИ ПРОФИЛЯ
--------------------------------------------------------------------------------

Каждый профиль — это отдельная секция с именем [Profile:Имя].
Имя профиля — это то, что вы видите в GUI. Пример: [Profile:Documents].

В одном config.ini может быть сколько угодно профилей.

--- paths ---
  Папки-источники. По одной на строку, с отступом.
  Тип: многострочный список путей.
  Обязательный параметр.
  Пример (один путь):
      [Profile:Documents]
      paths =
          C:/Users/user/Documents
  Пример (несколько путей):
      [Profile:All]
      paths =
          C:/Users/user/Documents
          C:/Users/user/Desktop
          D:/Projects
  Если несколько путей — в снимке они окажутся в подпапках с именами
  источников: Documents/..., Desktop/..., Projects/...
  Это защищает от коллизий (два desktop.ini из разных папок).

--- exclude ---
  Дополнительные исключения для этого профиля. Дополняют глобальные
  из [Exclude]. По одной маске на строку, с отступом.
  Тип: многострочный список.
  Необязательный параметр.
  Пример:
      exclude =
          *.psd
          *.ai
          *.iso
          node_modules
          node_modules/*

--- rotation_n ---
  Сколько последних РЕАЛЬНЫХ снимков хранить. 0 — не удалять никогда.
  no_change-снимки не считаются (они удаляются отдельно).
  Тип: целое число >= 0.
  По умолчанию: 0 (не удалять).
  Пример:
      rotation_n = 10

--- interval_min ---
  Интервал между проверками в минутах. Используется в режиме --watch
  и в GUI для напоминаний.
  Тип: целое число >= 1.
  По умолчанию: 30
  Пример:
      interval_min = 30

--- hash_enabled ---
  Считать SHA-256 для этого профиля. Переопределяет глобальную настройку.
  Тип: true / false.
  Пример:
      hash_enabled = true

--- ignore_hidden ---
  Игнорировать скрытые файлы/папки (начинающиеся с точки на Linux/macOS,
  или с атрибутом «скрытый» на Windows).
  Тип: true / false.
  По умолчанию: true.
  Пример:
      ignore_hidden = true

--- external_enabled ---
  Автосинхронизация на носители для этого профиля.
  Тип: true / false.
  Пример:
      external_enabled = true

--- external_rotation_n ---
  Сколько последних снимков хранить на носителе для этого профиля.
  Тип: целое число >= 0.
  Пример:
      external_rotation_n = 5

--- external_search_all ---
  Искать метку на всех томах для этого профиля.
  Тип: true / false.
  Пример:
      external_search_all = true


--------------------------------------------------------------------------------
  5. ПРИМЕРЫ
--------------------------------------------------------------------------------

--- Пример 1: Минимальный конфиг (один профиль) ---

[General]
backup_base = ~/SnapshotVault

[Profile:Documents]
paths =
    ~/Documents


--- Пример 2: Два профиля (документы и код) ---

[General]
backup_base = ~/SnapshotVault
external_enabled = true

[Profile:Documents]
paths =
    ~/Documents
    ~/Desktop
rotation_n = 10

[Profile:Projects]
paths =
    ~/Projects
exclude =
    node_modules
    node_modules/*
    .venv
    .venv/*
rotation_n = 20
interval_min = 15


--- Пример 3: Жёсткая экономия места ---

[General]
backup_base = D:/Backups/SnapshotVault
hash_enabled = false          ; не считать хэши (быстрее)
external_enabled = false      ; не синхронизировать на флешки
logging_enabled = false       ; не вести логи

[Exclude]
patterns =
    *.tmp
    *.bak
    *.old
    *.log
    .git
    .git/*
    node_modules
    node_modules/*

[Profile:Work]
paths =
    C:/Work
exclude =
    *.iso
    *.vmdk
    build
    build/*
rotation_n = 5                ; хранить только 5 снимков
hash_enabled = false


--- Пример 4: Синхронизация на флешку ---

[General]
backup_base = ~/SnapshotVault
external_enabled = true
external_rotation_n = 3
external_search_all = true

[Profile:Photos]
paths =
    ~/Pictures
rotation_n = 20
external_enabled = true
external_rotation_n = 5

Примечание: на флешке должна быть метка SV_BACKUP_ALLOW.txt в корне.
Содержимое: SnapshotVault backup marker


--- Пример 5: Несколько источников в одном профиле ---

[Profile:Everything]
paths =
    ~/Documents
    ~/Desktop
    ~/Downloads
    ~/Pictures
    ~/Music
rotation_n = 15
interval_min = 60
exclude =
    *.iso
    *.dmg
    *.vmdk
    *.mp4
    *.mkv

В снимке файлы окажутся в подпапках:
    Documents/...
    Desktop/...
    Downloads/...
    Pictures/...
    Music/...
Это защищает от коллизий имён.


--- Пример 6: Профиль только для чтения (без синхронизации) ---

[Profile:Archive]
paths =
    D:/Archive
rotation_n = 0                ; не удалять никогда
hash_enabled = true
external_enabled = false      ; не синхронизировать на флешки
interval_min = 1440           ; раз в сутки


--------------------------------------------------------------------------------
  6. ЧАСТЫЕ ОШИБКИ И КАК ИХ ИСПРАВИТЬ
--------------------------------------------------------------------------------

--- Ошибка: "MissingSectionHeaderError" или "ParsingError" ---
Причина: многострочное значение без отступа.
Пример неправильно:
    paths =
    C:/Users/user/Documents
    D:/Backup

Правильно (отступ 4 пробела):
    paths =
        C:/Users/user/Documents
        D:/Backup

--- Ошибка: "Профиль не найден" / профиль пропал ---
Причина: папка из paths не существует.
Решение: в GUI нажмите ПКМ → «Редактировать», укажите существующую папку.
Или в config.ini исправьте paths.

--- Ошибка: "Дублируется секция" ---
Причина: две секции с одинаковым именем.
Пример неправильно:
    [Profile:Documents]
    paths = ...
    [Profile:Documents]
    paths = ...

Решение: уберите дубликат.

--- Ошибка: "Не удалось прочитать config.ini" ---
Причина: файл повреждён (например, случайно удалили половину).
Решение: удалите config.ini — при следующем запуске программа создаст
новый с умолчаниями. Или восстановите из резервной копии.

--- Ошибка: "Хардлинки недоступны, копирую..." ---
Это НЕ ошибка. Причины:
  1. Папка-источник и backup_base на разных томах (дисках).
  2. Файловая система не поддерживает хардлинки (FAT32, exFAT).
  3. Нет прав на создание хардлинков.
Программа автоматически переключится на копирование. Снимки будут
занимать больше места, но данные сохранятся.

--- Ошибка: флешка не находится ---
Проверьте:
  1. Метка SV_BACKUP_ALLOW.txt в КОРНЕ флешки (не в подпапке).
  2. Содержимое метки: "SnapshotVault backup marker" (точное совпадение).
  3. external_search_all = true (если флешка определяется как внешний ЖД).
  4. На Linux: флешка смонтирована в /media/$USER/ или /run/media/$USER/.


--------------------------------------------------------------------------------
  7. ГОРЯЧИЕ СОВЕТЫ
--------------------------------------------------------------------------------

1. Не редактируйте config.ini в момент, когда программа делает снимок.
   Дождитесь окончания операции.

2. Перед серьёзными изменениями сделайте копию config.ini:
       copy config.ini config.ini.backup      (Windows)
       cp config.ini config.ini.backup        (Linux)

3. Для ручной правки используйте редактор с подсветкой INI (Notepad++,
   VS Code). Блокнот Windows тоже подойдёт, но следите за кодировкой —
   файл должен быть в UTF-8.

4. Если сомневаетесь — начните с минимального конфига (Пример 1) и
   добавляйте параметры по одному.

5. Проверить, что конфиг прочитан правильно, можно через CLI:
       snapshotvault-cli --action list
   Вы увидите список профилей и их статусы. Если профиль отсутствует —
   значит, paths указывает на несуществующую папку.


--------------------------------------------------------------------------------
  ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
--------------------------------------------------------------------------------

1. Запустите CLI-версию:
       snapshotvault-cli --action list
   Она покажет, какие профили загружены, а какие пропущены (с причиной).

2. Включите debug в [General]:
       debug = true
   И посмотрите backup.log в папке профиля.

3. Проверьте целостность:
       snapshotvault-cli --action integrity
   Это покажет, есть ли проблемы со снимками.

4. Если ничего не помогает — удалите config.ini и создайте заново
   (программа сделает это автоматически при следующем запуске).
